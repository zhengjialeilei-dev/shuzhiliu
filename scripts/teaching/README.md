# 教学项目质量检查

## 管理方式

`scripts/teaching-projects.json` 是构建工程的统一清单，当前包含 7 个项目。保留各工程自己的依赖锁文件、构建工具和发布物，不把独立教学代码塞进网站前端，也不改变作品上传方式。

新增工程时登记稳定 ID、标题、学科、源码目录、产物入口、验证级别。检查器会拒绝重复 ID、缺少锁文件/构建命令以及存在 package.json 却未登记的工程。`triangle-rotation` 当前为空目录，不作为已实现工程登记。

## 命令

在仓库根目录运行：

```bash
npm run teaching:list
npm run teaching:check
npm run teaching:build
npm run test:teaching
npm run test:all
```

新机器已安装主仓库依赖后，使用 `npm run teaching:build -- --install` 按各自锁文件安装并构建；该命令调用各工程的 `npm ci`，会重建对应 node_modules，但不上传作品或更新数据库。

GitHub Actions 的教学检查作为生产部署的前置任务：7 个工程构建与产物入口检查通过，且教学测试通过后，整站部署任务才可开始。工程源码不随主站部署包发布，仍需单独上传作品产物。

## 验证级别

- `build`：诗贯山河、梦回繁华、领奖台展开工坊。验证 TypeScript、构建和入口引用；尚未覆盖这些应用的完整交互流程。
- `interaction`：文言文推理馆、物理事故调查局、数学城市建造师、地球气候控制台。除了构建，还验证输入节点和焦点保留、数值联动、完成/重置流程及关键业务规则。
- Vitest 使用 jsdom 进行 DOM 回归，不等同于真实浏览器帧率测试；物理定时器使用可控测试时钟。
- `engines.test.ts` 验证的是当前教学模型的计算/状态约定，不构成对全部学科内容准确性的审定。

## 本轮局部更新约定

高频控制输入发出 `controls` 更新通知，只改变读数、图形参数和相关按钮。输入框、滑杆和主场景不被替换，也不重复绑定事件。进入页面、打开抽屉和重新开始等结构变化仍采用原有完整渲染，避免一次引入新的前端框架。

数学城市只有点击“落成”才记为完成；修改已验算但未落成的方案会取消本次验算结果。物理实验启动后锁定条件，记录启动时的参数，重新开始会取消未完成的计时器。
